# 订阅负载均衡（subscribe_lb）

把多台节点合成订阅里的**一个节点**。用户拉订阅时按「用户 + 组」从组内选一台，直接下发**这台节点的完整配置**——地址可以直接是 IP，各成员的端口 / 协议 / 认证 / 传输都可以不同。

适合：
- 入口域名被污染、DNS 轮询不稳定，想让订阅直接下发 IP；
- 同一线路有多个入口 IP，想把用户均匀分散到各个入口；
- 某个入口挂了，希望用户下次更新订阅时自动换到健康的入口。

## 安装

1. 后台「插件管理」→「上传插件」，选择 `subscribe_lb-x.y.z.zip`；
2. 安装 → 启用；
3. 打开控制台：`https://你的面板域名/{后台路径}/sub-lb`（`{后台路径}` 就是你进后台用的那段路径）。
   控制台使用后台的登录状态，请先在同一域名登录后台。

需要 Xboard 的定时任务在运行（官方 Docker 镜像默认就有）；巡检命令 `sub-lb:check` 每分钟执行一次。

## 使用

1. 在「节点管理」里正常建好各个节点（每个入口 IP 一个节点，或用下面的「入口子节点」）；
2. 控制台 →「新建组」：填展示名称（就是订阅里看到的节点名）、勾选成员；
3. 组内成员**倍率（含分时倍率）必须一致**；一台节点只能属于一个组；成员需保持「显示」开启才会参与分配；
4. 成员默认不再以自己的名字单独出现在订阅里（可在成员上勾「独立显示」）。

## 规则

- **分配**：首次随机；分配间隔（默认 60 分钟）内复用，复用不延后到期；到期后下一次更新订阅时重新随机（允许抽中原节点）。同一用户的所有客户端拿到同一个结果。
- **成员状态**：活跃 = 接收新分配；维护中 = 保留已有分配、不接新分配；停用 = 立即失效。
- **健康**（每组可选）：面板心跳（≤300 秒）/ TCP 探测（连续 2 轮失败判不可用，连续 3 轮成功才恢复）/ 两者都看 / 不检查；也可以对成员强制「可用 / 不可用」。
- **fail-open**：如果组内所有成员都被自动判为不健康（更可能是探测侧出问题），暂时忽略自动信号继续下发，只尊重人工强制不可用，避免整组从订阅消失。
- **容灾边界**：这是订阅侧的重新分配，不是连接中的即时切换——客户端必须再次更新订阅才会生效。
- **流量和计费**：完全按实际成员节点上报、按成员倍率计费，与组名无关。
- **停用组** = 组和成员都不下发；**删除组** = 解散，成员恢复为普通节点。

## 入口子节点（同一台机器的多个入口 IP）

一台机器有多个 IP，或者前面挂了多台转发机时：给承载节点（真正监听、上报流量的那个节点）建「子节点」（`parent_id` 指向承载节点、不绑定机器、`host` 填入口 IP），把承载节点和子节点放进同一个组即可。

- 巡检每分钟把承载节点的端口 / 协议参数 / 倍率 / 权限组等同步给子节点；
- 承载节点被隐藏、超流量上限或停用时，它的子节点一起下线；
- 子节点只是另一个连接地址，流量仍记在承载节点上。

## 域名入口自动解析

入口是域名、而对方会换 IP 的节点（比如第三方中转）：编辑组时填「域名入口解析」的来源节点 ID。面板服务器按间隔解析它的 A 记录（只取 IPv4），每个 IP 自动成为一个成员，订阅里下发 IP；IP 从 DNS 消失则自动停用、回来则自动启用。

> 取舍：下发 IP 后，对方换 IP 要等下一次解析 + 用户更新订阅才生效。对方一天换好几次 IP 的话，直接下发域名可能更合适。

## 命令行

```bash
php artisan sub-lb:status                      # 各组成员健康与分配人数（只读）
php artisan sub-lb:check                       # 立即巡检一次（平时由定时任务每分钟执行）
php artisan sub-lb:resolve [--group=ID]        # 立即解析域名入口
php artisan sub-lb:member <server_id> down --note="原因"   # 强制某成员不可用（auto / up 同理）
php artisan sub-lb:external <来源> --port=443 --up=1.1.1.1 --down=2.2.2.2   # 外部监控按 IP 同步健康
```

## 已知限制

- 只接管**订阅**（`client.subscribe.servers` 钩子）。用户面板里的「节点列表」页面仍会列出组内每一台成员（上游这里没有钩子），不影响订阅内容。
- 后台菜单里没有入口，需要用上面的控制台地址打开（可以加到浏览器书签）。
- 组状态告警走 Xboard 自带的 Telegram 通知（发给已绑定 Telegram 的管理员），可在插件配置里关闭。

## 卸载

插件管理 → 禁用即可停止生效（订阅立即恢复成各节点独立下发）；卸载会删除本插件的 4 张表（`sub_lb_*`），不会改动 `v2_server`。为入口子节点建的节点需要自己在节点管理里删除。
