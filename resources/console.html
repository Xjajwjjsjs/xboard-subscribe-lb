订阅负载均衡

每组在订阅里只出现一个节点，按「用户 + 组」分配成员并直接下发入口 IP。

规则说明（分配 / 健康 / 容灾边界）
  • 每组在订阅里只出现一个节点，名称 = 组的展示名称；连接参数（地址/端口/协议/认证/传输）、倍率、流量计费都来自实际分到的成员。
  • 按「用户 + 组」记录分配：首次随机；间隔内复用（不延后到期）；到期后下一次更新订阅时重新随机，允许抽中原节点。同一用户不同客户端/模板一致。
  • 成员状态：活跃接收新分配；维护中保留已有分配、不接新分配（没有健康的活跃成员时临时承接）；停用立即失效。成员不会再以自己的名字单独下发（除非勾选「独立显示」）。
  • 健康来源：面板心跳（≤ 秒）、TCP 探测（连续 轮失败判不可用，连续 轮成功才恢复，巡检停摆 秒后探测结果作废）、人工/外部强制。自动信号全部判不可用时视为探测侧故障，暂时忽略自动信号（fail-open），只尊重强制下线。
  • 不可用 / 停用 / 删除 / 失去用户权限的成员：用户下次更新订阅时提前改分配到其他合格成员。恢复后只承接新分配，不把已迁走的用户拉回。新增成员只承接后续分配，不打乱现有有效分配。
  • 容灾边界：这是订阅侧重新分配，不是连接中的即时切换——客户端必须再次更新订阅才会生效（Clash 系默认 24 小时自动更新一次）。组停用 = 组和成员都不下发；删除组 = 解散，成员恢复为普通节点。
